SQL 书写顺序和逻辑处理顺序

SQL 看起来从 SELECT 开始写，但数据库真正理解查询时，通常会先处理 FROM、JOIN 和 WHERE。它不是变量提升，而是 SQL 的解析规则。

一、先记住这句话

重点： SQL 的书写顺序，是给人看的语法顺序；SQL 的逻辑处理顺序，是数据库理解“数据从哪里来、怎么过滤、怎么分组、最后返回什么”的顺序。

二、常见查询的书写顺序

你写 SQL 时，一般按下面这个顺序写。

-- SQL 的常见书写顺序
SELECT 字段列表
FROM 主表
JOIN 关联表 ON 关联条件
WHERE 行级筛选条件
GROUP BY 分组字段
HAVING 分组后的筛选条件
ORDER BY 排序字段
LIMIT 返回条数 OFFSET 跳过条数;
书写顺序关键字你写它是为了什么
1SELECT声明最终想返回哪些字段。
2FROM声明数据来自哪张主表。
3JOIN ... ON声明要连接哪些表，以及表之间怎么匹配。
4WHERE声明普通行数据的筛选条件。
5GROUP BY声明按什么字段分组。
6HAVING声明分组统计之后的筛选条件。
7ORDER BY声明结果怎么排序。
8LIMIT / OFFSET声明最终返回多少条、跳过多少条。

三、数据库的逻辑处理顺序

逻辑顺序关键字数据库在做什么
1FROM先确定从哪张表开始取数据。
2JOIN ... ON把相关表连接起来，并根据 ON 条件匹配数据。
3WHERE对连接后的行数据做筛选。
4GROUP BY把筛选后的数据按字段分组。
5聚合函数计算 COUNT、SUM、AVG 等统计值。
6HAVING对分组后的结果继续筛选。
7SELECT决定最终输出哪些字段和表达式。
8DISTINCT去掉重复结果。
9ORDER BY对最终结果排序。
10LIMIT / OFFSET截取最终要返回的数据范围。
所以：表别名写在 FROM 里，但 SELECT 能使用它，是因为数据库会先理解数据来源和表别名，再决定 SELECT 返回什么。

四、为什么 SELECT 里能先看到表别名

这不是 JS 的变量提升。数据库会先解析整条 SQL，知道 users AS u 和 roles AS r 分别代表什么。

-- 虽然 SELECT 写在前面，但表别名来自 FROM 和 JOIN
SELECT
  u.id AS user_id,
  u.username,
  r.role_name
FROM users AS u
INNER JOIN user_roles AS ur ON u.id = ur.user_id
INNER JOIN roles AS r ON ur.role_id = r.id;
别名在哪里定义代表什么
uFROM users AS uusers 表。
urJOIN user_roles AS uruser_roles 表。
rJOIN roles AS rroles 表。

五、字段别名为什么不能随便在 WHERE 里用

WHERE 的逻辑处理顺序比 SELECT 早，所以很多情况下，WHERE 还不知道 SELECT 里起的字段别名。

-- 这个写法通常会报错：WHERE 早于 SELECT，WHERE 不认识 user_age
SELECT
  age AS user_age
FROM users
WHERE user_age >= 18;

正确写法是：在 WHERE 里使用真实字段名。

-- 正确写法：WHERE 使用真实字段 age
SELECT
  age AS user_age
FROM users
WHERE age >= 18;

六、为什么 ORDER BY 又能用 SELECT 别名

ORDER BY 的逻辑顺序在 SELECT 后面，所以它通常能使用 SELECT 中定义的字段别名。

-- ORDER BY 通常可以使用 SELECT 中定义的别名
SELECT
  age AS user_age
FROM users
ORDER BY user_age DESC;
对比记忆：WHERE 比 SELECT 早，所以通常不能用 SELECT 别名；ORDER BY 比 SELECT 晚，所以通常能用 SELECT 别名。

七、WHERE 和 HAVING 的区别

WHERE：分组前筛选行

先把不符合条件的行过滤掉，再进行分组统计。

-- 先筛选成年用户，再按年龄分组统计
SELECT
  age,
  COUNT(*) AS user_total
FROM users
WHERE age >= 18
GROUP BY age;

HAVING：分组后筛选组

先分组统计，再筛选统计结果。

-- 先按年龄分组，再只保留人数大于 1 的年龄组
SELECT
  age,
  COUNT(*) AS user_total
FROM users
GROUP BY age
HAVING COUNT(*) > 1;
简单记：WHERE 筛选原始行，HAVING 筛选分组后的统计结果。

八、ON 和 WHERE 在 JOIN 中的区别

ON：决定表怎么匹配

ON 是连接条件，说明两张表通过什么字段对应起来。

-- ON 表示文章表的 user_id 要匹配用户表的 id
SELECT
  a.id AS article_id,
  a.title,
  u.username
FROM articles AS a
INNER JOIN users AS u ON a.user_id = u.id;

WHERE：连接后再筛选

WHERE 是筛选条件，说明连接完成后只保留哪些记录。

-- 先连接文章和用户，再筛选用户 id 等于 1 的文章
SELECT
  a.id AS article_id,
  a.title,
  u.username
FROM articles AS a
INNER JOIN users AS u ON a.user_id = u.id
WHERE u.id = 1;
注意：在 INNER JOIN 中，部分条件放 ON 或 WHERE 结果可能一样；但在 LEFT JOIN 中差别会很明显，入门阶段先把“ON 管匹配，WHERE 管筛选”记牢。

九、完整复杂查询怎么按逻辑顺序看

看复杂 SQL 时，不要从第一行 SELECT 硬读。先找 FROM 和 JOIN，再看 WHERE、GROUP BY、HAVING，最后看 SELECT、ORDER BY、LIMIT。

-- 查询每个用户拥有多少个角色，只保留角色数大于 1 的用户
SELECT
  u.id AS user_id,
  u.username,
  COUNT(r.id) AS role_total
FROM users AS u
INNER JOIN user_roles AS ur ON u.id = ur.user_id
INNER JOIN roles AS r ON ur.role_id = r.id
GROUP BY u.id, u.username
HAVING COUNT(r.id) > 1
ORDER BY role_total DESC
LIMIT 10;
阅读顺序看哪里你要问自己什么
1FROM users AS u主表是谁？
2JOIN user_roles / roles连接了哪些表？靠什么字段连接？
3GROUP BY按什么分组？
4HAVING分组后保留哪些组？
5SELECT最终返回哪些字段？
6ORDER BY / LIMIT怎么排序？返回多少条？
