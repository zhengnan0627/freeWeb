后端如何使用数据库

前面学的是数据库本身。这一阶段开始把数据库接到后端：后端负责接收请求、执行 SQL、处理结果，再把安全且必要的数据返回给前端。

一、为什么前端不直接连数据库

数据库账号不能暴露

如果前端直接连数据库，数据库地址、账号、密码都会暴露给用户，这是非常危险的。

业务规则需要后端兜住

权限判断、参数校验、事务、日志、敏感字段过滤，这些都应该在后端处理。

记住：前端调用后端接口，后端再访问数据库。前端不应该直接操作数据库。

二、一次接口请求大概怎么流动

顺序位置做什么
1前端发起请求，比如获取用户列表。
2后端路由接收请求，解析参数。
3业务层检查权限、处理默认值、决定查什么数据。
4数据库层执行 SQL 或 ORM 查询。
5返回层过滤敏感字段，整理成前端需要的数据结构。

三、后端连接数据库通常用连接池

连接池可以复用数据库连接，避免每次请求都重新连接数据库。下面是 Node.js 中常见的思路示例。

/**
 * 创建 MySQL 连接池。
 * 实际项目中，账号密码应该放在环境变量里，不要写死在代码中。
 */
const pool = mysql.createPool({
  host: "127.0.0.1",
  port: 3306,
  user: "root",
  password: "你的数据库密码",
  database: "fullstack_study",
  waitForConnections: true,
  connectionLimit: 10
});
先理解概念：连接池就像后端提前准备好一组数据库连接，请求来了就借一个，用完再还回去。

四、后端查询用户列表

后端不应该无脑 SELECT *。列表接口只查前端需要展示的字段。

-- 用户列表接口只查询必要字段
SELECT id, username, age, created_at
FROM users
ORDER BY created_at DESC
LIMIT 10;

在 Node.js 里，执行查询通常会得到 rows，也就是数据库返回的行数据。

/**
 * 查询用户列表。
 * 这里只返回列表页需要展示的字段。
 */
async function listUsers() {
  const [rows] = await pool.query(`
    SELECT id, username, age, created_at
    FROM users
    ORDER BY created_at DESC
    LIMIT 10
  `);

  return rows;
}

五、参数化查询：不要拼接用户输入

用户输入不能直接拼进 SQL 字符串，否则可能产生 SQL 注入风险。

/**
 * 不推荐：把用户输入直接拼进 SQL，存在 SQL 注入风险。
 */
async function unsafeFindUser(username) {
  const sql = `SELECT id, username FROM users WHERE username = '${username}'`;
  const [rows] = await pool.query(sql);

  return rows;
}

更安全的写法是参数化查询。? 是占位符，具体值通过数组传入。

/**
 * 推荐：使用参数化查询，让数据库驱动处理用户输入。
 */
async function findUserByUsername(username) {
  const [rows] = await pool.query(
    "SELECT id, username FROM users WHERE username = ?",
    [username]
  );

  return rows;
}

六、分页接口怎么对应 SQL

前端常传 page 和 pageSize，后端把它们换算成 LIMIT 和 OFFSET。

/**
 * 分页查询用户列表。
 * page 从 1 开始，offset 表示跳过多少条。
 */
async function listUsersByPage(page, pageSize) {
  const safePage = Math.max(Number(page) || 1, 1);
  const safePageSize = Math.min(Math.max(Number(pageSize) || 10, 1), 100);
  const offset = (safePage - 1) * safePageSize;

  const [rows] = await pool.query(
    `
      SELECT id, username, age, created_at
      FROM users
      ORDER BY created_at DESC
      LIMIT ? OFFSET ?
    `,
    [safePageSize, offset]
  );

  return rows;
}

七、总数和列表通常分开查

查列表

-- 查询当前页用户列表
SELECT id, username, age, created_at
FROM users
ORDER BY created_at DESC
LIMIT 10 OFFSET 0;

查总数

-- 查询用户总数，用于前端分页组件
SELECT COUNT(*) AS total
FROM users;
前端视角：表格组件通常需要两部分数据：当前页列表和总条数。

八、不要把数据库字段原样全返回

数据库表里可能有密码、内部备注、删除标记、权限标识等字段。后端应该明确选择返回哪些字段。

/**
 * 返回给前端前，整理成明确的数据结构。
 * 这样即使数据库新增敏感字段，也不会自动暴露给前端。
 */
function toUserListItem(row) {
  return {
    id: row.id,
    username: row.username,
    age: row.age,
    createdAt: row.created_at
  };
}
真实项目：接口返回字段是后端的契约，不应该等于数据库表的全部字段。

九、后端事务写法

后端里事务一般会拿到一个专用连接，在这个连接上执行多条 SQL，成功就提交，失败就回滚。

/**
 * 使用事务完成转账。
 * 两个 UPDATE 必须一起成功，否则就回滚。
 */
async function transfer(fromId, toId, amount) {
  const connection = await pool.getConnection();

  try {
    await connection.beginTransaction();

    await connection.query(
      "UPDATE transaction_accounts SET balance = balance - ? WHERE id = ?",
      [amount, fromId]
    );

    await connection.query(
      "UPDATE transaction_accounts SET balance = balance + ? WHERE id = ?",
      [amount, toId]
    );

    await connection.commit();
  } catch (error) {
    await connection.rollback();
    throw error;
  } finally {
    connection.release();
  }
}

十、ORM 是什么

ORM 帮你生成 SQL

比如 Prisma、TypeORM 这类工具，可以让你用对象和方法操作数据库，而不是每次手写 SQL。

但不能只会 ORM

ORM 最终还是会生成 SQL。你理解 SQL，才能看懂慢查询、联表、索引和事务问题。

SQL 思维ORM 里对应什么
SELECT查询方法，例如 findMany、findFirst。
WHERE查询条件对象。
JOIN关系查询、include、relations。
TRANSACTIONORM 提供的事务 API。

十一、迁移 Migration 是什么

迁移就是把数据库结构变化记录成版本。比如新增 users 表、给 users 表加 email 字段，都应该留下可追踪记录。

-- 迁移文件里常见的内容：给用户表新增邮箱字段
ALTER TABLE users
ADD COLUMN email VARCHAR(100);
团队项目：不要只在 Navicat 里手动改表。真实项目通常要通过迁移文件管理数据库结构变化。
