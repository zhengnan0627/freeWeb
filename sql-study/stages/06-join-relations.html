表关系和 JOIN 联表

真实业务很少只查一张表。这一阶段学习如何用外键字段建立关系，再用 JOIN 把相关数据一起查出来。

一、为什么需要多张表

不要把所有数据塞进 users 表

用户信息、文章信息、订单信息属于不同业务对象，应该拆成不同表。

表之间靠 id 建立关系

比如文章表里的 user_id，表示这篇文章属于哪个用户。

Excel 类比：users 是一张用户 Sheet，articles 是一张文章 Sheet，articles 里的 user_id 用来指向 users 里的 id。

二、创建 articles 表

文章表用 user_id 记录作者是谁。这个字段会存 users 表中的用户 id。

-- 创建 articles 文章表
CREATE TABLE articles (
  -- 文章自己的唯一编号
  id INT PRIMARY KEY AUTO_INCREMENT,
  -- 作者 id，对应 users 表里的 id
  user_id INT NOT NULL,
  -- 文章标题，不能为空
  title VARCHAR(100) NOT NULL,
  -- 文章内容，可以为空
  content TEXT,
  -- 创建时间，不传值时默认当前时间
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

三、准备文章数据

这里假设 users 表里已经有 id 为 1、2、3 的用户。

-- 给不同用户插入几篇文章
INSERT INTO articles (user_id, title, content) VALUES
  (1, 'SQL 入门笔记', '记录 SELECT 和 WHERE 的学习内容'),
  (1, 'MySQL 排序分页', '记录 ORDER BY 和 LIMIT 的使用'),
  (2, '前端转全栈', '记录从前端学习后端和数据库的路线'),
  (3, 'JOIN 联表查询', '记录用户和文章如何关联查询');
注意：如果你的 users 表里没有对应 id，插入后联表查询时可能查不到作者信息。先确认 users 表里有哪些 id。

四、先分别查询两张表

查询用户表

-- 查看用户表中的 id 和用户名
SELECT id, username
FROM users;

查询文章表

-- 查看文章表中的文章和作者 id
SELECT id, user_id, title, created_at
FROM articles;
观察重点：articles 表里的 user_id 不是用户名，它只是指向 users 表中某个用户的 id。

五、INNER JOIN：只查匹配成功的数据

INNER JOIN 会把两张表中能匹配上的数据查出来。

-- 查询文章列表，同时带出作者用户名
SELECT
  articles.id,
  articles.title,
  users.username,
  articles.created_at
FROM articles
INNER JOIN users ON articles.user_id = users.id;
怎么理解 ON 条件

articles.user_id = users.id 表示：文章表里的作者 id，要等于用户表里的用户 id。

六、给表起别名，让 SQL 更短

真实项目里经常给表起别名。articles a 表示 articles 表临时叫 a，users u 表示 users 表临时叫 u。

-- 使用表别名简化联表查询
SELECT
  a.id,
  a.title,
  u.username,
  a.created_at
FROM articles a
INNER JOIN users u ON a.user_id = u.id;

七、LEFT JOIN：保留左表数据

LEFT JOIN 会保留左边表的数据。即使右边表没有匹配，也会先把左表记录查出来。

-- 查询所有文章，即使作者信息匹配不到也保留文章
SELECT
  a.id,
  a.title,
  u.username,
  a.created_at
FROM articles a
LEFT JOIN users u ON a.user_id = u.id;
JOIN 类型特点常见用途
INNER JOIN只保留两边匹配成功的数据只查有作者的文章
LEFT JOIN先保留左表数据，右表匹配不到就显示空文章列表中尽量保留文章记录

八、联表时字段名冲突怎么办

users 和 articles 都有 id、created_at。联表查询时建议给返回字段起别名。

-- 给查询结果字段起别名，避免前端拿到重复或含义不清的字段名
SELECT
  a.id AS article_id,
  a.title AS article_title,
  u.id AS author_id,
  u.username AS author_name,
  a.created_at AS article_created_at
FROM articles a
INNER JOIN users u ON a.user_id = u.id;
后端返回数据：AS article_id 这种别名，通常会变成接口返回对象里的字段名。

九、联表 + WHERE + ORDER BY

联表查询也可以继续使用筛选和排序。下面查询某个用户发布的文章，并按创建时间倒序排列。

-- 查询 id 等于 1 的用户发布的文章，并按时间倒序排列
SELECT
  a.id AS article_id,
  a.title,
  u.username AS author_name,
  a.created_at
FROM articles a
INNER JOIN users u ON a.user_id = u.id
WHERE u.id = 1
ORDER BY a.created_at DESC;
